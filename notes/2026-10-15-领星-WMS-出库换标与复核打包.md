## 1. 功能目标（观察）

* **角色**：仓库端操作员。
* **要解决的事**：
  * 换标：OMS 已提交的备货中转单，在「出库 → 换标」先扫单据号，再扫旧标，打出新标。没有卖家上传的新标文件时，扫旧标不会打；行内「打印条码」可以打系统生成的条码。
  * 复核 / 打包：没有名为「打包」的菜单。按产品单到待出库之后，行菜单里填装箱明细、再填托盘明细。PC「复核/验货」和「包裹复核」不接受这张备货中转单的单号。帮助中心把备货中转的出库前复核写成 PDA「复核出库」，步骤见 3.6。

## 3. 主流程

### 3.1 换标（现网已扫）

1. 出库 → 换标。默认「产品换标」。另一项是「箱换标」。
2. 页上黄条按账号所用控件显示。这一账号是领星控件，文案「未检测到领星控件点击安装」。「点击安装」下载的是 Windows 安装包 `xl-print-plugin-setup-v2.0.4.exe`。这台云端桌面是 Linux，安装包不能直接运行。页面检测到本机打印服务之后，黄条变成「领星打印 设置」，页脚从「打印机未连接」变成「打印机已连接」，打印机下拉可以选。证据：`screenshots/31-wms-live-relabel-scan.png`、`screenshots/32-wms-live-relabel-printed.png`。
3. 先扫备货中转出库单号。待处理的按产品 + 产品换标单可以直接扫进去，不必先点「提交拣货」。扫入后单据号锁定，右侧空态「请扫描备货中转出库单号」换成产品卡片和明细表。
4. 再扫旧标。换标产品框的占位是：FNSKU / SKU / 产品条码 / 自定义条码。
5. 有新标文件时：扫旧产品条码后提示「领星打印成功」。卡片上「打印/换标数量」变成 1/1。新标按 PDF、1 份交给本机打印服务。
6. 没有新标文件时：扫旧产品条码提示「当前产品无换标文件可打印」，打印数量保持 0。行内「打印新标文件」提示「新标文件不存在」。行内「打印条码」可以打，走浏览器打印，不走领星控件；打完打印数量从 0 变成 1，换标数量仍是 1。
7. 行上还有「完成」，会把扫描页清回空态。这次看完数量后没有点它做别的提交。

帮助中心写：不上传新标文件时，仓库扫描会由系统拼接生成。现网不会。系统条码是手动「打印条码」。

帮助中心还写：换标做完后回到待出库，编辑换标服务，填实际换标数量。有新标文件的那张按产品单现在在待出库，行菜单里有「编辑换标服务」，这次没有打开。仓里原有的一条按箱 + 产品换标单，在待拣货就能打开，见 4.3。

### 3.2 单据在备货中转列表里的位置

OMS 提交按产品 + 产品换标之后：

* 待处理出现按产品单：产品数量 1、换标服务「产品换标」、出库方式「按产品出库」、目的地类型「其他」、拣货单打印「未打印」。行上是「提交拣货」和「操作」。证据：`screenshots/30-wms-live-pending-by-product.png`
* 有新标文件的那张点了「提交拣货」。没有确认框。待处理少 1，待拣货多 1，行上变成「拣货」和「操作」，并出现提交时间。没有新标文件的那张留在待处理。
* 拣货确认之后：待拣货回到 0，待出库变为 2。其中 1 条是刚拣完的按产品单（当时箱数 0），另 1 条是仓里原来的按箱单（箱数 1）。这次没有去点原来那条。
* 产品库存：第一张单提交前总库存 5、可用 5、锁定 0；提交并刷新后总库存 5、可用 4、锁定 1。第二张单提交、以及后来拣货，没有再对库存。

待处理行的「操作」：编辑增值服务、下载换标文件、打印换标单、下载附件、打印发货清单、打印面单、更新期望到仓时间。没有「编辑换标服务」，也没有「上传附件」。

### 3.3 拣货

只对有新标文件的那张按产品单做了。

1. 待处理行点「提交拣货」。没有确认框，马上进待拣货。
2. 行上点「拣货」。页标题「备货中转拣货」。页眉是出库方式「按产品」、客户、总数量、状态「待拣货」。证据：`screenshots/33-wms-live-pick.png`
3. 行上已拣/应拣是 0/1，库存属性「正品」，拣货库位预填了已有库位，库位产品数量是 5，拣货数量预填 1。
4. 「确认」一开始是灰的。勾上这一行的复选框之后才能点。点行上的「添加」会多出一条空库位（带「移除」），空行还在时「确认」仍然是灰的。去掉空行、勾上复选框、数量保持 1，点「确认」。
5. 没有再弹确认框。提示「操作成功」，回到备货中转列表，这一条到待出库。

### 3.4 装箱和托盘（待出库）

待出库的按产品行，行上有「确认出库」和「操作」。这次没有点「确认出库」，也没有点工具条的「出库」。

「操作」菜单：编辑增值服务、编辑换标服务、下载换标文件、打印换标单、填写装箱明细、上传附件、下载附件、填写托盘明细、打印拣货单、打印发货清单、打印面单、标记异常、更新期望到仓时间。没有点「标记异常」，没有打开「编辑换标服务」。

填写装箱明细（页标题「上传装箱明细」）：

1. 打开时没有箱子。上方「出库托盘数」默认 0。单位按钮在「公制」（cm / kg）和「英制」（in / lb）之间切换，默认公制。
2. 「添加箱子」出一行。箱子数量默认 1。必填是长、宽、高、箱子重量、单箱数量。箱条码规则默认「不自增」，可选：不自增、自增箱号、自增箱号（自定义）、FBA箱唛号、美客多箱唛号。列头「批量」是给各行统一改这个规则的小层，里面是同一组选项，点了取消。
3. 没加 SKU 就点页底「确认」：提示「箱子需要添加SKU」。SKU 列的「添加」打开「添加产品」，勾选后「已选择 1 个产品」，点「确定」。自定义箱条码空着也能过。
4. SKU 已加、尺寸重量和单箱数量仍空：长宽高和重量旁提示「不能为空」，并提示「请检查所填的数据」。单箱数量同样是必填。
5. 填了 10×10×10 cm、重量 1 kg、单箱数量 1、箱子数量 1、规则「不自增」，点「确认」。回到列表。这一条仍是待出库，箱数从 0 变成 1。证据：`screenshots/34-wms-live-pack.png`

填写托盘明细：有箱子之后可以进。行菜单先弹出小层，字段是「出库托盘数」（默认 0），按钮是「填写托盘明细 / 取消 / 确定」。点小层里的「填写托盘明细」进入托盘页，没有被拦住。没有箱子时会不会拦住，这次没试。

托盘页：单位是「公制 / 英制」两个单选。列是托盘数量、托盘尺寸、托盘重量、自定义托盘条码、托盘条码规则、关联箱子、箱子数量、操作。规则默认「不自增」，另外还有「自增托盘号」「自增托盘号(自定义)」，没有装箱那种 FBA / 美客多选项。「添加托盘」增加一行，行上可以「移除托盘」。关联箱子点「添加箱子」，弹层列出刚保存的那一箱：数量 1、自定义箱条码空、尺寸 10*10*10、重量 1。箱类型号是系统生成的，末尾是 `-F1`。页下方还有一块「仓库装箱明细」，列是箱类型号、自定义箱条码、物流跟踪号、尺寸、重量、箱内产品数量、出库箱数、出库产品数，这次显示「暂无数据」；箱子只在上面的「添加箱子」弹层里出现。勾上这一箱后，托盘行的关联箱子带上这个箱类型号。填了 20×20×20 cm、重量 2 kg、托盘数量 1，点「确认」，提示「操作成功」，回到列表。待出库仍是 2，已出库仍是 0。证据：`screenshots/35-wms-live-pallet.png`

OMS 列表在这之后仍是仓库处理中，没有变成已出库。

### 3.5 复核和称重（扫了这张待出库单，进不去）

* 出库 → 复核/验货。一单一件扫波次单号。把页面上的出库单号、以及装箱地址里的另一张单号分别扫进去，都提示「请扫描正确的单号」，右侧仍是「请扫描波次单号开始分拣」。
* 切到一单多件，扫描标签是出库单号/物流跟踪号/格子号。同样两个号，还是「请扫描正确的单号」，空态不变。
* 出库 → 包裹复核。扫描标签是波次单号。同样两个号，提示「请扫描正确的单号」，空态仍是「请扫描波次单」。
* 出库 → 称重。同样两个号，提示「请扫描正确的单据号」，空态仍是「请扫描出库单号/物流跟踪号开始称重」。没有点「称重完成」。
* 出库 → 换单。这次没有再扫。

帮助中心把备货中转的复核写成 PDA「复核出库」，只处理待出库。PC 这两页不吃这张单的单号，和帮助中心的分工一致。步骤见 3.6。

2. 在 PDA 上登录 WMS，从「设置」进入下载 PDA，下安装包再装。
3. 帮助页还给出一条直接下载地址。链接带签名参数，笔记里不收录。

#### 3.6.2 大货拣货

《通过PDA实现拣货》：https://help.xlwms.com/12d0/d5f9/b3bb/1f4a ，页脚 2026-08-26。备货中转处理篇把电脑端填拣货写成方式一，把 PDA 写成方式二，路径是「拣货 → 大货拣货」。

按产品出库：

1. 扫描或输入出库单号，也可以在拣货列表里点这张单。概况页列出要拣的 SKU 和库位，可以在库位视图和 SKU 视图之间切换。
2. 点「开始拣货」。依次扫描或输入库位编码、Barcode、数量，再点确认。同一张单可以分多次拣完。

按箱出库：

1. 同样先扫出库单号，或从拣货列表进入。概况页列出推荐库位、箱类型号、自定义箱条码，可以在库位视图和箱视图之间切换。
2. 点「开始拣货」。扫描或输入库位编码后，页面列出要拣的箱库存，再输入或扫描条码。同一张单可以分多次拣完。

Barcode 可以扫 SKU、产品条码、其他条码、FNSKU。点条码左侧的感叹号，能看当前产品的其他条码和图片。

WMS 设置里打开「PDA拣货不扫库位」之后，可以不扫库位，只扫产品条码。配图上，这个勾选和「PDA复核后立即出库」出现在「设置 → 出库」的一件代发分组。

同一篇里的波次拣货、边拣边分，对象是一件代发出库单。换标拣货的对象是 FBA 换标服务单。备货中转走上面的大货拣货。

这篇常见问题里的两句，现网没有在 PDA 上打出来：「未找到波次号!」（扫的不是波次号，或波次不属于当前 PDA 仓库）；「请扫描正确的拣货单」（这篇把它写在 FBA 换标服务单，单据要是待拣货）。

#### 3.6.3 复核出库

《通过PDA实现复核出库》：https://help.xlwms.com/12d0/d5f9/b3bb/199b ，页脚 2026-07-16。

场景写成：货大，不方便搬到电脑前。路径：PDA → 复核出库。只处理待出库的备货中转出库单。备货中转处理篇的常见问题把「出库前扫描面单和箱唛，再确认出库」指到这一篇。

按产品出库：

1. 扫描出库单号或 Barcode，定位到单据，并展示详情。
2. 再扫 Barcode，定位到明细，并可以继续扫 Barcode 累计数量。已扫数量要小于等于待出库数量。
3. 确认数量后点「提交」。

按箱出库：

1. 扫描出库单号、自定义箱条码或箱类型号，定位到单据。
2. 再扫自定义箱条码或箱类型号，确认出库数量。已扫箱子数量要小于等于待出库数量。
3. 点「提交」。

配图：扫描前标题是「复核出库」，扫描框占位「请扫描」。按产品时，框上的标签写成「出库单号/自定义箱条码/箱类型号/Barcode」，图上把 Barcode 单独标出。按箱时，标签是「出库单号/自定义箱条码/箱类型号」。扫进单据之后的两屏，标题写成「扫描出库」。页头字段有类型、客户、物流渠道、期望到仓时间、已扫/待出库，中间有「备注」。按产品的行上有 FNSKU、Barcode、已扫/待出库和数量框。按箱的行上有箱类型号、自定义箱条码、已扫/待出库，以及可展开的「产品信息」。底部按钮是「提交」。

备注：定位到单据后点「备注」，可以写文字，也可以上传图片和附件。配图上附件带红星，类型示例是「其他」，用加号上传，文案是「支持上传20张照片且单张大小不超过10M」。备注计数 0/255。按钮是「保存」。

两个开关的正文路径都是「WMS → 设置 → 出库」：

* 「PDA复核后立即出库」：PDA 做完出库复核，单据自动变成已出库，不用再在电脑上点出库。
* 「PDA复核出库/复核验货时，数量满足后自动提交」：复核数量达到订单数量就自动提交。禁止超额。

两个可以单独开，也可以一起开。一起开时，足额复核之后自动提交，并直接出库。配图里这两个勾选和「PDA拣货不扫库位」画在同一张「设置 → 出库」图上，落在一件代发分组。

数量少于预报：常见问题写，系统提示「箱型的出库数存在差异，请检查」。先在 WMS 设置打开「调整数量出库」，再做差异出库。库存和库龄按实际出库记，计费要到 OMP 管理后台手动调整。配图把「开启【调整数量出库】」放在「设置 → 出库」的备货中转分组。另一张配图是按产品出库、已扫数量少于待出库，弹出「箱型的出库数存在差异，是否确认提交？」，按钮是「取消」「确定」。确定之后提示「出库成功」，回到复核出库的空扫描页。

其他两句：

* 扫描备货中转出库单号提示「订单不存在，请检查」：单据不是待出库。
* 复核出库用于备货中转出库单。复核验货用于一件代发出库单。

#### 3.6.4 扫描出库

《通过PDA扫描出库》：https://help.xlwms.com/12d0/d5f9/b3bb/69a6 ，页脚 2026-07-27。首页上是单独一格。

1. 打开「扫描出库」。
2. 选出库类型：一件代发出库，或备货中转出库。
3. 备货中转只接受待出库。一件代发接受待复核或待出库。
4. 扫描或手输物流跟踪号，或出库单号。核对包裹信息后点「确认出库」。确认后同步到电脑端。

页面上的重量，要先在系统里称过才有数，否则是 0。称过就按称重后的重量计费，没称过就按系统里的包裹重量计费。

#### 3.6.5 复核验货和备货中转分开

《通过PDA实现复核验货》：https://help.xlwms.com/12d0/d5f9/b3bb/8c61 ，页脚 2026-07-17。对象是一件代发，状态是待复核或待出库。PC「复核/验货」拒绝这张备货中转单，见 3.5。

打开「复核验货」，扫物流跟踪号或出库单号，再扫 SKU 或产品条码，也可以手填已扫数量。没扫完时「提交」是灰的。提交成功后同步到电脑，单据转到待出库。3.6.3 的两个自动开关，这篇也写了一遍。

同一波次里，只要有一张出库单的包裹做过包裹复核，再做常规复核会提示「该出库单已在包裹复核菜单中进行过复核操作，不允许再进行常规复核」。跟踪号不对时提示「请输入正确的单号」。这篇写 PDA 复核验货暂不支持扫描序列号，并建议改走 PC 复核验货的 Barcode 框。
